# The One Hit Wonder : Solving MIDHNP with Coppersmith

The challenge was almost centralized to one `while True` loop, which I was cocky enough to claim this was going to be a cinch... how wrong I was. The service openly gives $p$, how many bits are leaked, and lets us choose input. I spent a while wondering whether the chosen-input oracle itself could be abused, meaning whether some carefully selected $t_i$ values could force outputs with exploitable structure. It is the same general adversarial mindset as a chosen-plaintext attack, even though this is not literally a CPA. Clearly it wasnt. And the more annoying part was that both values we need are hidden was behind a modular inverse.

For every tap, the challenge computes
$$
z_i = v(t_i + u)^{-1}\mod p
$$
and returns the top $k$ bits:
$$
y_i = \operatorname{MSB}_k(z_i).
$$

For this instance, $p$ is 1536 bits, prime, and the challenge only keeps around 58% of the output, meaning not the exact mod inverse value. This partial leak, repeated across values sharing the same hidden $u,v$ starts to make it look like an HNP (Hidden Number Problem). 

## MSB Leak into Small Errors

From working through LWE and homomorphic encryption, I have gotten very used to thinking about secrets in terms of a known relation plus some bounded error. This is obviously a very different setting, since the challenge is not intentionally adding noise, but the same question came to mind: how much missing information is too much?

Let
$$
X = 2^{n-k}
$$
Since $y_i$ contains the high bits of $z_i$, the exact value can be written as
$$
z_i = y_iX + e_i
$$
where the unknown low part satisfies
$$
0 \leq e_i < X
$$

Hence, we now have $p,t_i,y_i$ known, $e_i$ small unknown, $u,v$ large hidden. If we can recover $e_i$, then we can reconstruct the exact $z_i$, and then recover $u,v$. Which sounds easier to say than actually doing it.

However, as stated before we have two hidden values:

## Choosing the Inputs

The challenge let us choose each $t_i$, and we only get around eight queries. There is also no reason to make the equations worse than they need to be, so we can just choose $0,1,2,3,4,5,6,7$ for the eight taps. Then for every exact sample:
$$
z_i(u + t_i)\equiv v\mod p.
$$

Substitute
$$
z_i = y_iX + e_i = \bar{x}_i
$$
then every sample satisfies
$$
\bar{x}_iu + t_i\bar{x}_i-v\equiv 0 \mod p
$$

Given $e_i$ small, $u,v$ unknowns modulo $p$, then we want to eliminate them from the final lattice. $\S 3.2$ btw of the Ding et al. paper.

## Elimination of Hidden Values

With the determinant construction, for $d = 1$, choose $i,j,k$ such that 
$$
\det(M)\quad:\quad M = \begin{bmatrix}
    t_i\bar{x}_i & \bar{x}_i & 1\\
    t_j\bar{x}_j & \bar{x}_j & 1\\
    t_k\bar{x}_k & \bar{x}_k & 1
\end{bmatrix}
$$

and the rows come from $u,v$ and some constant. Which satisfy the relations of the sample modulo $p$, and the determinant vanishes modulo $p$. And does not include $u,v$ also.

To hold the hand of a typical CTF player not in academia, myself years ago:
$$
\begin{align*}
  t_i\bar{x}_i + \bar{x}_iu - v &\equiv 0\mod p\\
  \begin{pmatrix}t_i\bar{x}_i& \bar{x}_i & 1\end{pmatrix}\begin{pmatrix}1\\u\\-v\end{pmatrix} &\equiv 0\mod p\\
  M\begin{pmatrix}1\\u\\-v\end{pmatrix} &= \vec{0}\mod p.
\end{align*}
$$
Given we are working over $\mathbb{F}_p$, finite field and our nonzero vector, this implies we have $M$ having a nontrivial kernel. Therefore, $M$ is singular over $\mathbb{F}_p$. Hence $\det(M) \equiv 0 \mod p$, coming down to basic linear algebra. We all took that as computer scientists, right? Q.E.D.

Now that we have a polynomial only in the small low-bit variable, the solver builds the general $d$ construction here:

```python
def fundamental(t, b, idx, d, p, R):
    mod = p ** d
    F = PolynomialRing(Zmod(mod), R.variable_names(), order="degrevlex")

    x = F.gens()
    rows = []

    for i in idx:
        z = x[i] + F(b[i])
        row = []

        for j in range(d, -1, -1):
            row.append(F(t[i]) ** j * z)

        for j in range(d - 1, -1, -1):
            row.append(F(t[i]) ** j)

        rows.append(row)

    f = matrix(F, rows).det()

    lm = f.monomials()[0]
    lc = f.monomial_coefficient(lm)

    f *= lc ** -1

    return lift(f, R, mod)
```

For a given $d$, this gives a degree $d+1$ polynomial that vanishes modulo $p^d$ at the true low-bit values.

## Moving to d = 2.

For $d = 2$, the determinant used five samples, giving a $5\times 5$ determinant, which you can see the paper work out. After normalization, the resulting polynomial is a degree $3$, vanishes at modulo $p^2$ at the true low-bit values, and hence we get the final working lattice. Given our eight small unknowns:

$$
e_0,\ldots,e_7
$$
For the $d = 2$ construction, we have squarefree monomials through degree 3, $1,e_i,e_ie_j,e_ie_je_k$ which results in
$$
\binom{8}{0} + \binom{8}{1} + \binom{8}{2} + \binom{8}{3} = 93
$$
or, that our monomial basis has dimension 93, and hence the final lattice is exactly $93x93$.

## Building Shift Polynomials

Starting with $p^2$:
```python
for monomial in monomials:
    shifts[monomial] = p ** 2 * monomial
    level[monomial] = 2
```
Which vanishes at modulo $p^2$. The $d=1$ determinants vanish modulo $p$, so multiplying them by $p$ gives valid relations modulo
$p^2$:
```python
for idx in combinations(range(count), 3):
    f = fundamental(t, b, idx, 1, p, R)
    degree2.append((idx, f))

    lm = f.monomials()[0]

    if lm in shifts and level[lm] > 1:
        shifts[lm] = p * f
        level[lm] = 1
```
Those are degree 2. Multiplying by one additional variable gives degree-3 shifts:
```python
for idx, f in degree2:
    for j in range(count):
        if j in idx:
            continue

        g = p * f * x[j]
        lm = g.monomials()[0]

        if lm in shifts and level[lm] > 1:
            shifts[lm] = g
            level[lm] = 1
```
Then the actual $d=2$ determinants already vanish modulo $p^2$, so they are the strongest degree-3
relations:
```python
for idx in combinations(range(count), 5):
    f = fundamental(t, b, idx, 2, p, R)
    lm = f.monomials()[0]

    if lm in shifts:
        shifts[lm] = f
        level[lm] = 0
```
At this point I finally had the Coppersmith lattice I wanted.

### Quick Coppersmith recall

In the multivariate Coppersmith construction we are using here, we build several polynomials that share the same bounded root modulo a sufficiently high power of the modulus, scale the variables by their expected root bounds, and use their coefficient vectors to build an integer lattice. `jvdsn`’s `small_roots` code follows this same idea for lattice creation, then we reduce and reconstruct integer polynomials and solve for the roots.

## Building the Coppersmith Lattice

I used the generic small root utilities from [jvdsn/crypto-attacks](https://github.com/jvdsn/crypto-attacks) instead of manually implementing all of the lattice scaling and polynomial reconstruction. Every low bit variable satisfies the same bound:
$$
|e_i| < X=2^{n-k}.
$$
The lattice is created with:
```python
bounds = [X] * count

L, monomials = small_roots.create_lattice(
    R,
    list(shifts.values()),
    bounds,
    order="degrevlex"
)
```
For the actual reduction I used [flatter](https://github.com/keeganryan/flatter):
```python
B = L.LLL(algorithm="flatter")
```
I already had `flatter` installed from another challenge, and it was significantly faster for this lattice than just sitting around waiting on the default Sage reduction. After lattice reduction, `jvdsn` reconstructs the short vector relations as integer polynomials:
```python
polys = small_roots.reconstruct_polynomials(
    B,
    None,
    p ** 2,
    monomials,
    bounds
)
```
Then I solve the resulting polynomial system using a Groebner basis:
```python
roots = next(
    small_roots.find_roots(
        R,
        polys,
        method="groebner"
    )
)
```
That finally gives
$$
e_0,\ldots,e_7.
$$
At that point, all eight exact modular inverse outputs are known:
$$
z_i=y_iX+e_i.
$$
The lattice part is completely over.

## Recovering u and v

Okay, the final step is recovering the hidden values:

Given two samples:
$$
z_0(u+t_0)\equiv v\mod p\qquad z_1(u+t_1)\equiv v\mod p,
$$
then
$$
z_0u+t_0z_0\equiv z_1u+t_1z_1\mod p.
$$
Therefore,
$$
u(z_0-z_1)\equiv t_1z_1-t_0z_0\mod p.
$$
Assuming the denominator is invertible, which it is for the samples here,
$$
u=(t_1z_1-t_0z_0)(z_0-z_1)^{-1}\mod p.
$$
Then
$$
v=z_0(u+t_0)\mod p.
$$
In code:
```python
u = ((t[1] * z[1] - t[0] * z[0]) * inverse_mod(z[0] - z[1], p)) % p
v = z[0] * (u + t[0]) % p
```
Submit those two values to option 4 and the challenge gives the flag.

At this point, I am no longer blindly implementing equations from a paper. Locally, I know the real $e_i$, so I can test whether the construction actually behaves the way I expect. For $d=1$, the determinant vanished modulo $p$. For $d=2$, I now get a degree-3 polynomial that vanishes modulo $p^2$ at root. That is enough evidence for me during a CTF to keep going and start building shifts around it.

If the determinant does not vanish at the real errors, then my algebra or implementation is wrong. If the determinant works but the lattice does not reduce into useful relations, then the problem moved somewhere else: maybe the scaling is wrong, maybe the monomial basis is bad, maybe the modulus power is not strong enough, or maybe the reconstruction step is failing.

From there, we just keep following the construction: build the shifts, throw them into the lattice, recover the $e_i$, reconstruct the exact $z_i$, and solve for $u,v$ like above. Finally giving us our flag.

## Solve Script

```python
from sage.all import *
from pwn import *
from shared import small_roots
from itertools import combinations
import sys

def lift(f, R, mod):
    xs = R.gens()
    out = R(0)

    for powers, coeff in f.dict().items():
        coeff = ZZ(coeff)

        if coeff > mod // 2:
            coeff -= mod

        term = R(1)

        for i in range(len(xs)):
            term *= xs[i] ** powers[i]

        out += coeff * term

    return out


def fundamental(t, b, idx, d, p, R):
    mod = p ** d
    F = PolynomialRing(Zmod(mod), R.variable_names(), order="degrevlex")

    x = F.gens()
    rows = []

    for i in idx:
        z = x[i] + F(b[i])
        row = []

        for j in range(d, -1, -1):
            row.append(F(t[i]) ** j * z)

        for j in range(d - 1, -1, -1):
            row.append(F(t[i]) ** j)

        rows.append(row)

    f = matrix(F, rows).det()

    lm = f.monomials()[0]
    lc = f.monomial_coefficient(lm)

    f *= lc ** -1

    return lift(f, R, mod)


def recover(p, n, k, samples):
    count = len(samples)
    X = 2 ** (n - k)

    t = []
    b = []

    for ti, yi in samples:
        t.append(ZZ(ti))
        b.append(ZZ(yi) << (n - k))

    names = [f"x{i}" for i in range(count)]
    R = PolynomialRing(ZZ, names, order="degrevlex")
    x = R.gens()

    monomials = [R(1)]

    for degree in range(1, 4):
        for idx in combinations(range(count), degree):
            term = R(1)

            for i in idx:
                term *= x[i]

            monomials.append(term)

    shifts = {}
    level = {}

    for monomial in monomials:
        shifts[monomial] = p ** 2 * monomial
        level[monomial] = 2

    degree2 = []

    for idx in combinations(range(count), 3):
        f = fundamental(t, b, idx, 1, p, R)
        degree2.append((idx, f))

        lm = f.monomials()[0]

        if lm in shifts and level[lm] > 1:
            shifts[lm] = p * f
            level[lm] = 1

    for idx, f in degree2:
        for j in range(count):
            if j in idx:
                continue

            g = p * f * x[j]
            lm = g.monomials()[0]

            if lm in shifts and level[lm] > 1:
                shifts[lm] = g
                level[lm] = 1

    for idx in combinations(range(count), 5):
        f = fundamental(t, b, idx, 2, p, R)
        lm = f.monomials()[0]

        if lm in shifts:
            shifts[lm] = f
            level[lm] = 0

    bounds = [X] * count

    L, monomials = small_roots.create_lattice(R, list(shifts.values()), bounds, order="degrevlex")

    B = L.LLL(algorithm="flatter")

    polys = small_roots.reconstruct_polynomials(B, None, p ** 2, monomials, bounds)

    roots = next(
        small_roots.find_roots(R, polys, method="groebner")
    )

    low = []

    for i in range(count):
        low.append(ZZ(roots[x[i]]))

    z = []

    for i in range(count):
        z.append(b[i] + low[i])

    u = (
        (t[1] * z[1] - t[0] * z[0])
        * inverse_mod(z[0] - z[1], p)
    ) % p

    v = z[0] * (u + t[0]) % p

    return u, v
```
